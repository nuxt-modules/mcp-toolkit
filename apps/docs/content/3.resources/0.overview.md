## Choose resources for content

Resources expose content a client can read by URI. Tools perform operations; prompts prepare conversations. A client decides how to discover and attach resource content, so presenting it to a model depends on the host.

Create default exports under `server/mcp/resources`. Filenames supply names and titles, while your definition supplies its URI and MIME type.

```ts [server/mcp/resources/help.ts]
import { defineMcpResource } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpResource({
  uri: 'docs://help',
  description: 'How to use this MCP server',
  mimeType: 'text/plain',
  handler: () => 'Use the greet tool to greet someone by name.',
})
```

A string becomes one text content item at the requested URI. Return an explicit `contents` result for multiple entries or binary data.

## Choose a resource form

| Definition | Use |
| --- | --- |
| `uri` | One concrete address, such as `docs://help` |
| `uriTemplate` | A family of addresses, such as `docs://guides/{slug}` |
| `list` | Enumerate template members |
| `complete` | Suggest template variable values |

Metadata belongs at the top level of the definition. There is no `file` shorthand or nested `metadata` object in the beta. Read files or application data inside the handler.

Require verified [scopes](/getting-started/oauth#require-scopes-on-definitions) for private reads. Static metadata remains listed; protect the endpoint itself if the catalog is sensitive.
