## Assign each endpoint a root

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    servers: {
      default: { dir: 'mcp' },
      admin: {
        dir: 'mcp-admin',
        auth: { tokens: [process.env.MCP_ADMIN_TOKEN!] },
      },
    },
  },
})
```
```text [Project structure]
server/
  mcp/
    tools/search.ts
    resources/help.ts
  mcp-admin/
    tools/admin-stats.ts
```

The public endpoint never discovers the admin definitions. There is no global pool, handler attribution field, or orphan filter.

## Overlay roots deliberately

A `dir` array orders roots by priority. For each root, Nuxt considers the app before its extended layers. The first file at a given relative path wins. This is a file overlay, not a name-based merge: different relative files advertising the same name still fail validation.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: { dir: ['mcp-overrides', 'mcp'] },
})
```

An app's `server/mcp-overrides/tools/search.ts` wins over the same relative tool in later roots. The first root containing `plugins.*` supplies discovered plugins; ambiguous matches within that root remain errors.

## Inspect the generated catalog

Generated exports follow the route slug. `/mcp` exports `mcp`; `/mcp/admin` exports `mcpAdmin`. Changing the route changes that generated export name. Read `definitions` or use `notify` through `nitro-mcp-toolkit/servers`.

The build reports what each endpoint discovers and warns about empty or near-miss directories. A file outside all scanned roots is not registered unless you compose it explicitly.
