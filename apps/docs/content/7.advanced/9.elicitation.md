## Use the modern request and retry flow

Modern MCP uses multi round-trip requests: return an interim input-required result, let the client gather input, then process the retried original operation. The callback runs again; it is not suspended on a server-side session. See the [MRTR specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr).

The toolkit re-exports the shared engine helpers. The old `useMcpElicitation()` wrapper is removed.

## Ask for a non-sensitive value

```ts [server/mcp/tools/welcome.ts]
import { z } from 'zod'
import {
  canRequestInput, defineMcpTool, getElicitedContent,
  getInputResponses, inputRequired, mcpElicit,
} from '@nuxtjs/mcp-toolkit/server'

const profile = z.object({ name: z.string().min(1) })
const requests = {
  profile: mcpElicit({
    message: 'What name should I use?',
    requestedSchema: {
      type: 'object',
      properties: { name: { type: 'string', title: 'Name', minLength: 1 } },
      required: ['name'],
    },
  }),
}

export default defineMcpTool({
  description: 'Greet someone, asking for a name when the client supports it',
  inputSchema: z.object({ name: z.string().min(1).optional() }),
  handler: ({ name }, event) => {
    if (name) return `Hello ${name}!`
    const response = getInputResponses(event, requests).profile
    if (response && response.action !== 'accept') return 'No name was provided.'
    const content = getElicitedContent(event, requests, 'profile')
    if (content) return `Hello ${profile.parse(content).name}!`
    if (!canRequestInput(event, requests.profile)) {
      throw new Error('This client cannot request a name. Call the tool with the name argument.')
    }
    return inputRequired(event, { inputRequests: requests })
  },
})
```

The request map gives response helpers the same keys and inferred fields as the question. Inferred response types describe what was requested, so validate the submitted content before using it.

Handle decline and cancel explicitly. Reading accepted content alone cannot distinguish a refusal from a first call; repeatedly asking after refusal can create a loop. The ordinary `name` argument gives legacy clients and clients without form support a usable path.

## Check the required capability

`canRequestInput(event, request)` checks the protocol era and the specific interaction mode. A URL request needs URL support; form support alone is insufficient. `inputRequired` also checks those requirements and reports unsupported capabilities explicitly.

`getInputResponses` reads supplied responses, `getElicitedContent` reads accepted form content, `getMissingInputs` returns unanswered requests, and `getSupportedInputs` filters a request map to supported entries. These helpers are request-scoped.

## Use URL mode for external interaction

```ts [server/utils/connect-request.ts]
import { mcpElicitUrl } from '@nuxtjs/mcp-toolkit/server'

export const connectRequest = mcpElicitUrl({
  message: 'Connect your account on the application website.',
  url: 'https://example.com/account/connections',
})
```

Present this through a capability-checked input-required result. Verify the application's completed connection server-side before using it; a client acceptance response is not proof of authorization.

Do not collect passwords, access tokens, or payment credentials through form mode. Use an appropriate external website for sensitive interactions. See [elicitation requirements](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation).

## Protect carried state

For state that influences authorization or business logic, use `defineRequestState`, bind it to verified identity, validate resumed input, and reauthorize the operation. Signed state is not encrypted or automatically single-use. See [application state](/advanced/sessions#carry-a-signed-continuation).

The default dual protocol mode keeps ordinary operations usable for 2025 clients; the toolkit's input-required helpers require modern support. Test both paths without claiming every client can render an interaction.
