## Keep endpoint catalogs explicit

Each endpoint owns the directories it discovers. The beta removes `enabled(event)`, per-request definition resolvers, and `useMcpServer()` registration/removal. A shared endpoint does not mutate its catalog when a different user connects.

Use `mcp.servers` for different catalogs, endpoint authentication for private metadata, and definition scopes for operation permissions. Groups, tags, and `X-MCP-Tools` are catalog selection aids, not authorization.

## Require scopes on the current invocation

```ts [server/mcp/tools/whoami.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Read the verified user identifier',
  scopes: ['profile:read'],
  annotations: { readOnlyHint: true, openWorldHint: false },
  outputSchema: z.object({ userId: z.string() }),
  handler: (event) => {
    const userId = event.context.oauth?.sub
    if (!userId) throw new Error('A verified user is required.')
    return { userId }
  },
})
```

Missing verified claims or scopes fail closed. The static metadata remains listed after endpoint authentication. Resource-template enumeration and resource/prompt completion callbacks check scopes before invoking application code.

The engine's extension decorators are modern-only; using one to hide a catalog would not establish authorization for legacy requests. Keep access decisions in the shared invocation checks and application services.

## Notify after application data changes

```ts [server/utils/mcp-notifications.ts]
import { mcp } from 'nitro-mcp-toolkit/servers'

export function helpUpdated() {
  mcp.notify.resourceUpdated('docs://help')
}
```

Call this after committing an application update. It broadcasts through the selected endpoint's supported notification channels. Inside a definition use `event.context.mcp.notifier` so a shared definition notifies the endpoint serving that request.

`toolsChanged()`, `resourcesChanged()`, and `promptsChanged()` notify clients to reload catalogs; they do not register definitions. Production file discovery is a build-time operation. A new deployed catalog requires the corresponding build and deployment.

The engine's `event.context.mcp.notify` remains a callable request-scoped function. Do not overwrite it with the toolkit's endpoint notifier.
