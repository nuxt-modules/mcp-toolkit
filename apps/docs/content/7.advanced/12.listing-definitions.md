## Read a specific endpoint

```ts [server/api/mcp-catalog.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { mcp } from 'nitro-mcp-toolkit/servers'

export default defineEventHandler(() => mcp.definitions.filter(
  definition => definition.kind === 'tool' && definition.tags?.includes('readonly'),
))
```

The generated `mcp` export belongs to `/mcp`. An endpoint at `/mcp/admin` exports `mcpAdmin`; export names follow the route slug. Generated types appear during Nuxt preparation.

`definitions` contains JSON-friendly summaries: `kind`, `name`, optional `title`, `description`, `group`, `tags`, `scopes`, resource `uri`, and a discovered file's relative `file` path. It is the full endpoint catalog, not a per-user filtered view.

## Filter plain values

Use `Array.filter` and `map` for group, tag, kind, or scope comparisons. Filtering a catalog response does not change registered tools or authorize operations. Protect a catalog route with normal application authentication before exposing private metadata; endpoint authentication does not automatically protect a separate API route.

The beta removes global `listMcp*` and `getMcp*` helpers, handler attribution filters, `orphansOnly`, and `enabled()` filtering. Compose definitions explicitly when a route needs raw definitions rather than summaries.

## Build a discovery card

```ts [server/routes/.well-known/mcp/server-card.json.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { mcp } from 'nitro-mcp-toolkit/servers'

export default defineEventHandler(() => ({
  name: 'Example MCP',
  endpoint: '/mcp',
  tools: mcp.definitions.filter(definition => definition.kind === 'tool')
    .map(({ name, description }) => ({ name, description })),
}))
```

This is an application discovery-card example, not a claim that this JSON shape is a core MCP protocol response. Protocol clients still use the shared engine's discovery/listing methods. Authentication remains independent of advertising an endpoint.
