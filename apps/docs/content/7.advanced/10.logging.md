## Keep diagnostics in application logging

The beta removes `useMcpLogger` and its session-based wrapper. Use your application logger and the retained tool-call hook for server metrics. MCP protocol Logging is deprecated in the modern specification; it is separate from application observability.

```ts [server/plugins/mcp-metrics.ts]
import { defineNitroPlugin } from 'nitropack/runtime'

export default defineNitroPlugin((app) => {
  app.hooks.hook('mcp:tool:called', ({ name, result, durationMs }) => {
    console.info({ tool: name, durationMs, failed: 'isError' in result && result.isError === true })
  })
})
```

This records duration and failure status without copying private arguments, token values, or complete results. Configure retention and log destinations in your application's logging system. A throwing observer reaches the caller, so handle destination failures explicitly.

## Report progress to the current client

```ts [server/mcp/tools/count-values.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Count a supplied list of values',
  inputSchema: z.object({ values: z.array(z.string()) }),
  outputSchema: z.object({ count: z.number() }),
  handler: ({ values }, event) => {
    event.req.signal.throwIfAborted()
    event.context.mcp.progress?.(0, values.length, 'Counting')
    const count = values.length
    event.context.mcp.progress?.(count, count, 'Complete')
    return { count }
  },
})
```

Progress uses the client's progress token and a supported notification channel. Do not invent a token or assume every host displays updates. Pass `event.req.signal` into long-running fetches or application services so a cancelled request can stop the work.

The engine's callable `event.context.mcp.notify` carries request notifications. Endpoint catalog/resource notifications live separately at `event.context.mcp.notifier` and generated `handler.notify`.

If maintaining protocol logging for an existing client, use the engine's request context and its revision rules. Keep secrets out of client-visible messages and do not depend on a legacy session log level for modern requests.
