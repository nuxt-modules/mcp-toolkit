## Define complete input schemas

`inputSchema` accepts a complete Standard Schema object. With Zod, wrap the fields in `z.object(...)`; a raw shape such as `{ id: z.string() }` is no longer a tool input schema.

```ts [server/mcp/tools/calculate-total.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Calculate a total with an optional multiplier',
  inputSchema: z.object({
    values: z.array(z.number()).min(1).describe('Values to add'),
    multiplier: z.number().default(1).describe('Multiply the sum by this value'),
  }),
  outputSchema: z.object({ total: z.number() }),
  handler: ({ values, multiplier }) => ({
    total: values.reduce((sum, value) => sum + value, 0) * multiplier,
  }),
})
```

Input validation runs before your handler. Defaults are applied by the schema, so `multiplier` is a number inside the callback even when the caller omits it. The toolkit also accepts supported Valibot and ArkType schemas through its shared definition contract.

| Input | Handler signature |
| --- | --- |
| A complete `inputSchema` | `(args, event) => result` |
| No arguments | `event => result`, with no `inputSchema` declaration |

A no-argument tool does not need a Zod import. Keep the import if you still use Zod for `outputSchema` or another schema.

## Validate structured output

`outputSchema` describes the data your handler returns. It remains a supported part of the API, with return-type inference and runtime validation:

```ts [server/mcp/tools/bmi-calculator.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

const bmiOutput = z.object({
  bmi: z.number(),
  category: z.enum(['underweight', 'normal', 'overweight', 'obese']),
})

export default defineMcpTool({
  description: 'Calculate Body Mass Index from height and weight',
  annotations: { readOnlyHint: true, openWorldHint: false },
  inputSchema: z.object({
    heightM: z.number().positive().describe('Height in meters'),
    weightKg: z.number().positive().describe('Weight in kilograms'),
  }),
  outputSchema: bmiOutput,
  handler: ({ heightM, weightKg }): z.input<typeof bmiOutput> => {
    const bmi = Number((weightKg / (heightM * heightM)).toFixed(2))
    const category = bmi < 18.5 ? 'underweight'
      : bmi < 25 ? 'normal'
        : bmi < 30 ? 'overweight' : 'obese'

    return { bmi, category }
  },
})
```

Returning `{ bmi, category }` produces both `structuredContent` and a JSON text content block. Clients receive the same advertised output shape across the modern and legacy protocol paths.

An invalid output is a protocol error: it means the server violated its advertised contract. Correct the handler or its schema rather than returning successful data that does not match. Ordinary thrown application errors become `isError` tool results instead.

## Return a protocol envelope explicitly

Use `toolResult()` when a tool with an output schema needs custom content blocks or an explicit result envelope:

```ts [server/mcp/tools/health.ts]
import { z } from 'zod'
import { defineMcpTool, toolResult } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Read service health',
  outputSchema: z.object({ status: z.enum(['ok', 'degraded']) }),
  handler: () => toolResult({
    content: [{ type: 'text', text: 'The service is responding.' }],
    structuredContent: { status: 'ok' },
  }),
})
```

Without the wrapper, an object returned alongside `outputSchema` is treated as schema data, including objects with fields named `content`, `structuredContent`, or `isError`. The wrapper makes the intent explicit.

## Return ordinary values or media

Without `outputSchema`, the toolkit normalizes common return values:

| Return value | Result |
| --- | --- |
| String, number, or boolean | One text content block |
| Plain object or array | JSON text content |
| `null` | Empty content |
| A full tool result | Its supplied content and metadata |

Use `imageResult(base64, mimeType)` or `audioResult(base64, mimeType)` for binary media:

```ts [server/mcp/tools/example-image.ts]
import { defineMcpTool, imageResult } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Return a one-pixel example PNG',
  handler: () => imageResult(
    'iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mP8/x8AAwMCAO+jRZkAAAAASUVORK5CYII=',
    'image/png',
  ),
})
```

For multiple content blocks, return a full result. If the tool also has an output schema, wrap that result in `toolResult()`.
