## Groups and tags

Groups and tags organize a catalog. Set them as typed properties; the toolkit advertises the corresponding metadata:

```ts [server/mcp/tools/admin/status.ts]
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  group: 'operations',
  tags: ['readonly', 'health'],
  description: 'Read the operations service status',
  annotations: { readOnlyHint: true, openWorldHint: false },
  handler: () => ({ status: 'ready' }),
})
```

A subdirectory such as `tools/admin/status.ts` infers the group `admin`. An explicit `group` overrides that inferred value. Neither groups nor tags enforce access control.

## Give each endpoint its own directories

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    servers: {
      default: { dir: 'mcp' },
      admin: {
        dir: 'mcp-admin',
        auth: { tokens: [process.env.MCP_ADMIN_TOKEN!] },
      },
    },
  },
})
```

The public endpoint scans `server/mcp`; `/mcp/admin` scans `server/mcp-admin`. Definitions in the admin directory never enter the public catalog. Put sensitive catalog metadata behind its own endpoint authentication.

Nuxt layers contribute to each endpoint's directories. The app overrides the same relative file from extended layers, and earlier configured roots take priority. See [endpoint migration](/getting-started/beta-migration#endpoints).

## Check verified scopes on invocation

With endpoint OAuth configured, add `scopes` to a definition to require all listed scopes. The engine checks verified `event.context.oauth` claims before running the operation, including application enumeration and completion callbacks.

A scope requirement does not hide static tool metadata. The beta removes `enabled(event)` and session-bound visibility; use endpoint authentication for private catalogs and invocation checks for private operations. See the [migration guide](/getting-started/beta-migration#authorization-and-catalogs).

## Read the generated catalog

```ts [server/api/mcp-catalog.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { mcp } from 'nitro-mcp-toolkit/servers'

export default defineEventHandler(() => mcp.definitions.filter(
  definition => definition.kind === 'tool' && definition.tags?.includes('readonly'),
))
```

The `definitions` array is a JSON-friendly catalog. Filtering this response does not change the endpoint's authorization or tool registrations. Apply your normal route authentication before exposing a private catalog view.

## Accept client tool selection

Clients may send `X-MCP-Tools` with comma-separated names from `tools/list`. The header narrows tool availability for that request; it never grants permission. Unknown names return HTTP 400, and authentication still runs.

Use this for client-specific tool selection alongside endpoint ownership and invocation authorization. It replaces neither of them.
