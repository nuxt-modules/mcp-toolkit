Tools are functions an MCP client can call to retrieve data or perform an action. Export one definition per file under `server/mcp/tools`. Nuxt supplies discovery and auto-imports; the shared Nitro engine handles the protocol.

This section describes the 1.0 beta API. Follow the [migration guide](/getting-started/beta-migration) when updating a 0.x application.

## Create a typed tool

Use a complete schema for the input and the output. This example validates the arguments, infers their types, and advertises the result shape to clients:

```ts [server/mcp/tools/bmi-calculator.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

const bmiOutput = z.object({
  bmi: z.number(),
  category: z.enum(['underweight', 'normal', 'overweight', 'obese']),
})

export default defineMcpTool({
  description: 'Calculate Body Mass Index from height and weight',
  annotations: { readOnlyHint: true, openWorldHint: false },
  inputSchema: z.object({
    heightM: z.number().positive().describe('Height in meters'),
    weightKg: z.number().positive().describe('Weight in kilograms'),
  }),
  outputSchema: bmiOutput,
  handler: ({ heightM, weightKg }): z.input<typeof bmiOutput> => {
    const bmi = Number((weightKg / (heightM * heightM)).toFixed(2))
    const category = bmi < 18.5 ? 'underweight'
      : bmi < 25 ? 'normal'
        : bmi < 30 ? 'overweight' : 'obese'

    return { bmi, category }
  },
})
```

The plain return value becomes `structuredContent`, with a JSON text fallback for clients that consume text. You do not need to construct an MCP response envelope for ordinary data.

`outputSchema` remains optional. When declared, it narrows the callback's return type and validates the result. See [schemas and handlers](/tools/schema-handler) for complete results, media, and validation errors.

## Omit schemas for tools without arguments

```ts [server/mcp/tools/ping.ts]
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Check that the MCP server is responding',
  handler: () => 'pong',
})
```

Leave out `inputSchema` when there are no arguments. Do not add `z.object({})` or import a schema library just to describe an empty input. A tool with only an `outputSchema` still needs the library used to define that output.

## Use the current request

With an input schema, a handler receives `(args, event)`. Without one, it receives `event`:

```ts [server/mcp/tools/request-info.ts]
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Read the current request identifier',
  handler: event => ({ requestId: event.req.headers.get('x-request-id') }),
})
```

Use the explicit event for verified identity, cancellation, and protocol context. Keep business logic in application services, and never capture a user's identity in a definition shared across requests.

## Discover names and endpoints

`bmi-calculator.ts` becomes the tool name `bmi-calculator` and title `Bmi Calculator`. Set `name` or `title` when a different spelling is useful.

The default server scans `server/mcp`. Configure [independent endpoints](/tools/groups-organization#give-each-endpoint-its-own-directories) with `mcp.servers` when a server needs different definitions or authentication. Each endpoint discovers its own roots; the public catalog does not inherit private definitions.
