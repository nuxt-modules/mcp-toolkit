## Read a configured file on Node

Set `README_PATH` to a file available in the deployed Node application. The public resource URI is independent of the actual filesystem location:

```ts [server/mcp/resources/readme.ts]
import { readFile } from 'node:fs/promises'
import { defineMcpResource } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpResource({
  uri: 'docs://readme',
  description: 'Project documentation',
  mimeType: 'text/markdown',
  handler: async () => {
    const path = process.env.README_PATH
    if (!path) throw new Error('The documentation file is not configured.')
    return readFile(path, 'utf8')
  },
})
```

The client cannot choose the filesystem path. A failed read throws a resource error; do not return `isError` inside resource contents or expose private filesystem details as document text.

## Read a Nitro server asset

For a Nuxt 4/Nitro 2 application, put content under `server/assets` and use Nitro's server-asset storage mount:

```ts [server/mcp/resources/guide.ts]
import { useStorage } from 'nitropack/runtime'
import { defineMcpResource } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpResource({
  uri: 'docs://guide',
  description: 'Bundled application guide',
  mimeType: 'text/markdown',
  handler: async () => {
    const text = await useStorage('assets:server').getItem<string>('guide.md')
    if (text === null) throw new Error('Guide not found')
    return text
  },
})
```
```md [server/assets/guide.md]
# Application guide

Use the documented MCP tools for this application.
```

Choose the asset/storage API for your deployed Nitro version. The explicit filesystem example requires Node; it does not establish Worker filesystem support. Private documents also need endpoint authentication, scopes, and application ownership checks.

See [resource templates](/resources/templates-and-handlers) for application identifiers and [content results](/resources/content-metadata-errors) for binary data.
