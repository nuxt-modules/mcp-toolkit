## Fetch, validate, and cache public data

Cache reusable upstream work with Nitro, then expose the result through a typed tool. This Nuxt 4 / Nitro 2 example caches each public product for ten minutes:

```ts [server/mcp/tools/get-product.ts]
import { defineCachedFunction } from 'nitropack/runtime'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'
import { z } from 'zod'

const productSchema = z.object({
  id: z.string(),
  name: z.string(),
})

const getProduct = defineCachedFunction(async (id: string) => {
  const response = await fetch(
    `https://api.example.com/products/${encodeURIComponent(id)}`,
  )
  if (!response.ok) throw new Error('The product service is unavailable.')
  return productSchema.parse(await response.json())
}, {
  name: 'mcp-public-product',
  maxAge: 600,
  swr: false,
})

export default defineMcpTool({
  description: 'Get a public product',
  annotations: { readOnlyHint: true, openWorldHint: true },
  inputSchema: z.object({ id: z.string().min(1) }),
  outputSchema: productSchema,
  handler: ({ id }) => getProduct(id),
})
```

Replace the example URL with your product service. `productSchema.parse()` validates data before it enters the cache, while `outputSchema` validates the tool's structured result. Clients also receive a JSON text fallback.

The cached function lives outside the handler. Its arguments form the default cache key; `maxAge` is in seconds, and `swr: false` waits for fresh data after expiry. See [errors and caching](/tools/errors-caching) for shared storage, private-data keys, worker lifecycle, and Nitro 3 imports.

## Use the current request explicitly

The callback receives validated arguments followed by the current MCP event. A tool without an input schema receives the event as its first argument. This avoids needing `useEvent()` or enabling async context just to read request information:

```ts [server/mcp/tools/request-language.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Read the preferred language sent with this request',
  outputSchema: z.object({ language: z.string().nullable() }),
  handler: event => ({ language: event.req.headers.get('accept-language') }),
})
```

The Nitro 2 adapter preserves middleware context on this event. Resolve private identities from verified application or OAuth context, authorize each call, and pass the identity into any cached function's arguments. Do not cache request events or capture a user's identity in a shared definition.

MCP callbacks use H3 v2 events even in a Nitro 2 host. A library requiring a native H3 v1 event needs host integration; do not force the type with a cast. Keep reusable business logic in services that accept ordinary values.
