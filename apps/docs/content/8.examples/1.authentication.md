## Choose the endpoint credential

For user authorization, configure an OAuth resource server. For a controlled service integration, a static bearer token can protect an entire endpoint. API keys and OAuth access tokens have different issuance and discovery flows; a browser session alone does not establish MCP authorization.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    servers: {
      default: { dir: 'mcp' },
    },
  },
})
```

```ts [server/mcp/index.ts]
import { createMcpOAuth, defineMcpServer } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpServer({
  oauth: createMcpOAuth({
    resource: 'https://example.com/mcp',
    authorizationServers: ['https://auth.example.com'],
    jwt: { jwks: 'https://auth.example.com/.well-known/jwks.json' },
    scopesSupported: ['profile:read'],
  }),
})
```

The runtime server configuration holds the prepared OAuth instance and the generated module mounts RFC 9728 metadata at `/.well-known/oauth-protected-resource/mcp`. A missing or invalid token returns HTTP 401 with a challenge pointing to that metadata. Verification callbacks and any private verifier credentials stay at runtime. Existing static `mcp.oauth` and per-server OAuth configuration remain supported; configure authentication in one place per endpoint.

```ts [server/mcp/tools/whoami.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Read the verified user identifier',
  scopes: ['profile:read'],
  annotations: { readOnlyHint: true, openWorldHint: false },
  outputSchema: z.object({ userId: z.string() }),
  handler: (event) => {
    const userId = event.context.oauth?.sub
    if (!userId) throw new Error('A verified user is required.')
    return { userId }
  },
})
```

See [the OAuth guide](/getting-started/oauth) for provider connectors, metadata paths, audience validation, and per-endpoint configuration.

## Apply an endpoint access policy

Add `authorize` alongside runtime `oauth` to check a verified identity before allowing access to any definition. This example requires an organization claim issued by the configured provider:

```ts [server/mcp/index.ts]
import { defineMcpServer } from '@nuxtjs/mcp-toolkit/server'
import { clerk } from '@nuxtjs/mcp-toolkit/oauth/clerk'

export default defineMcpServer({
  oauth: clerk({ resource: 'https://example.com/mcp' }),
  authorize: async (identity) => identity.org_id === 'org_example',
})
```

`authorize(identity, event)` receives a verified identity with a required `sub` and the current MCP event. It can await an application membership lookup using `identity.sub`. Other claims depend on the provider and verifier. Returning `false` returns HTTP 403 without an authentication challenge; invalid or missing credentials return HTTP 401 before the policy runs.

Per-definition `scopes` still apply, and application queries must enforce ownership and tenant boundaries. `scopesSupported` only advertises scopes; verified `scope` or `scp` claims determine whether a scoped invocation is allowed. Static catalog metadata remains listed for authenticated clients, even when a definition requires additional scopes.

## Use a static service token

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  runtimeConfig: { mcpToken: '' },
  mcp: { auth: './server/mcp/auth.ts' },
})
```

```ts [server/mcp/auth.ts]
import { defineMcpAuth } from '@nuxtjs/mcp-toolkit/server'
import { useRuntimeConfig } from 'nuxt/server'

export default defineMcpAuth({
  schemes: ['bearer'],
  validate: ({ token }) => token === useRuntimeConfig().mcpToken,
})
```

Set `NUXT_MCP_TOKEN` when starting the server and configure the client to send `Authorization: Bearer <token>`. The engine refuses missing or incorrect credentials, including when no token is configured. File discovery stays enabled.

Direct `auth.tokens` options are also available, but module configuration embeds their values at build time. Use a runtime auth file for deployment secrets. Do not embed the credential in public documentation, a badge, a deeplink, or a tool argument. A static credential does not populate a user-specific OAuth subject or scopes by itself.

## Compose OAuth manually

Prefer `defineMcpServer({ oauth: createMcpOAuth(options) })` in a discovered directory for JWT verification, provider adapters, and request-aware `verify(token, event)` callbacks. The module mounts protected-resource metadata automatically. For service credentials, use a runtime [auth file](/getting-started/configuration#read-authentication-at-runtime). Manual composition is useful for custom routing or an explicit definition collection. The following JWT example also shows the metadata route that manual composition must mount.

```ts [server/utils/mcp-oauth.ts]
import { createMcpOAuth } from '@nuxtjs/mcp-toolkit/server'

export const oauth = createMcpOAuth({
  resource: 'https://example.com/private-mcp',
  authorizationServers: ['https://auth.example.com'],
  jwt: { jwks: 'https://auth.example.com/.well-known/jwks.json' },
  scopesSupported: ['profile:read'],
})
```
```ts [server/mcp-private/tools/whoami.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  name: 'whoami',
  description: 'Read the verified user identifier',
  scopes: ['profile:read'],
  annotations: { readOnlyHint: true, openWorldHint: false },
  outputSchema: z.object({ userId: z.string() }),
  handler: (event) => {
    const userId = event.context.oauth?.sub
    if (!userId) throw new Error('A verified user is required.')
    return { userId }
  },
})
```
```ts [server/routes/private-mcp.ts]
import { createMcpHandler } from '@nuxtjs/mcp-toolkit/server'
import { oauth } from '../utils/mcp-oauth'
import whoami from '../mcp-private/tools/whoami'

export default createMcpHandler({
  name: 'private-mcp',
  oauth,
  tools: [whoami],
})
```
```ts [server/routes/.well-known/oauth-protected-resource/private-mcp.ts]
import { defineEventHandler } from 'nuxt/server'
import { oauth } from '../../../utils/mcp-oauth'

const headers = {
  'access-control-allow-origin': '*',
  'access-control-allow-methods': 'GET, OPTIONS',
  'access-control-allow-headers': '*',
}

export default defineEventHandler((event) => {
  if (event.req.method === 'OPTIONS') return new Response(null, { status: 204, headers })
  if (event.req.method !== 'GET') {
    return new Response(null, { status: 405, headers: { ...headers, allow: 'GET, OPTIONS' } })
  }
  return Response.json(oauth.metadata, { headers })
})
```

`createMcpHandler` accepts the prepared `oauth` instance and exposes it as `handler.oauth`. It also accepts `authorize(identity, event)` alongside `oauth`. `oauth.metadataPath` identifies this metadata URL. Use the public resource origin consistently; it is also carried in authentication challenges. The configured module mounts metadata through its native adapter automatically, while a manual route owns its host HTTP integration.

For opaque tokens, replace the `jwt` option with `verify(token, event)` backed by your provider's resource-aware verifier, keeping `resource` and `authorizationServers`. Populate verified `event.context.oauth` claims for identity/scopes. Do not accept a token merely because it exists or belongs to another API.

DPoP is unsupported. Built-in JWT verification rejects `cnf` claims; custom verifiers must reject proof-bound tokens too. Runtime OAuth uses issuer discovery and does not mount the root authorization-server compatibility proxy retained by static module configuration.

Test no credential, valid tokens, wrong issuer/audience, expiry, denied endpoint authorization, missing scopes, proof-bound tokens, and concurrent users. Full provider login, client registration, consent, and refresh require provider/client tests as part of beta validation.
