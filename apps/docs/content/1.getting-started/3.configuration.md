## Configure the default server

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: { name: 'Example MCP', websiteUrl: 'https://example.com/docs/mcp' },
})
```

Without `servers`, the module scans `server/mcp` and mounts `/mcp`. Configuration is resolved into generated server code at build time. Private credentials and live authentication callbacks belong in a runtime auth file, referenced by `auth`.

## Configure independent servers

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    servers: {
      default: { dir: 'mcp' },
      admin: {
        dir: 'mcp-admin',
        auth: './server/mcp-admin/auth.ts',
      },
    },
  },
})
```

Defining `servers` replaces the implicit default entry. Include `default` when you want `/mcp` as well as named endpoints. Each server inherits top-level server options, then applies its own overrides. `default` uses the base `route`; other keys default to `<route>/<key>`.

Each `dir` is relative to every Nuxt layer's server directory. A directory array orders roots by priority; the first root containing a relative definition file wins. The app overrides extended layers. See [directory ownership](/handlers/organization).

## Read authentication at runtime

Keep the endpoint in `mcp.servers` and export its authentication options from the referenced file:

```ts [server/mcp-admin/auth.ts]
import { defineMcpAuth } from '@nuxtjs/mcp-toolkit/server'
import { useRuntimeConfig } from 'nuxt/server'

export default defineMcpAuth({
  schemes: ['bearer'],
  validate: ({ token }) => token === useRuntimeConfig().mcpAdminToken,
})
```

Declare `runtimeConfig: { mcpAdminToken: '' }` in `nuxt.config.ts`, then set `NUXT_MCP_ADMIN_TOKEN` when starting the server. The token is read during authentication; it is not embedded in generated endpoint code. Missing or invalid credentials receive the engine's 401 challenge on modern and legacy requests.

Relative auth paths resolve from the project root. Nuxt aliases such as `~~/server/mcp-admin/auth.ts` and absolute paths are supported. A missing module fails the build; a missing or invalid default export fails when the endpoint loads. Both cases refuse requests. The auth file uses the engine's `AuthOptions`, including async `validate`, API-key schemes, and `resourceMetadataUrl`.

Static `auth.tokens` values remain available, but those values are embedded at build time. Use a runtime auth file for private configuration. An endpoint cannot combine `auth` and `oauth`.

## Choose server options

| Option | Behavior |
| --- | --- |
| `route` | Base route, `/mcp` by default; each server may override it |
| `dir` | Definition root or ordered roots; defaults to `mcp` or `mcp-<key>` |
| `name`, `version`, `title`, `description`, `icons`, `websiteUrl` | Server identity and presentation |
| `instructions` | Workflow guidance advertised to clients |
| `era` | `dual` by default; `modern` serves only the modern revision |
| `session` | Optional legacy protocol sessions; application storage stays separate |
| `auth` | Static bearer/API-key options or a runtime auth-file reference |
| `oauth` | JWT resource-server verification and discovery metadata |
| `origin` | Browser-origin policy, including loopback protection |
| `limits` | Engine request limits |

`auth` and `oauth` cannot be combined on one server. `scopesSupported` advertises OAuth scopes; a definition's `scopes` enforces them on invocation. See [OAuth setup](/getting-started/oauth).

## Choose Nuxt integration options

| Option | Default | Behavior |
| --- | --- | --- |
| `enabled` | `true` | Enable the module |
| `autoImports` | `true` | Register server helpers/types and the install component |
| `inspector.headers` | unset | Pass local Inspector authentication headers |
| `llms` | `true` | Add endpoint discovery when `nuxt-llms` is installed |
| `servers` | implicit default | Configure named endpoints |

## Allow browser origins deliberately

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    origin: { allow: ['https://console.example.com'] },
  },
})
```

The default accepts same-origin loopback pages and rejects other browser origins. The loopback restriction protects local servers from DNS rebinding. `allow` adds explicit origins. Requests without an `Origin` header are unaffected by the default check. Origin validation and HTTP CORS headers are separate concerns.

The old `allowedOrigins`, `browserRedirect`, `defaultHandler`, `sessions`, and handler-file options are removed. Use `websiteUrl` for a documentation link and the [migration guide](/getting-started/beta-migration) for replacements.
