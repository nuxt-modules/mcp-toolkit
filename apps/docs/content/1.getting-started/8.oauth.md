## Connect an authorization provider

The toolkit acts as the OAuth **resource server**. Your authorization provider handles login, client registration, consent, and access-token issuance. MCP clients discover that provider through the endpoint's protected-resource metadata. See the [MCP authorization model](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization).

Configure the provider to issue access tokens for the MCP resource URL. Browser session cookies and tokens issued for another API are not interchangeable with those tokens.

## Configure JWT verification

Replace the resource, issuer, and JWKS URLs with your deployed endpoints:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    oauth: {
      resource: 'https://example.com/mcp',
      authorizationServers: ['https://auth.example.com'],
      jwt: { jwks: 'https://auth.example.com/.well-known/jwks.json' },
      scopesSupported: ['profile:read'],
    },
  },
})
```

The module mounts RFC 9728 metadata at `/.well-known/oauth-protected-resource/mcp` for this resource. An authentication failure returns a 401 challenge pointing to that metadata.

Verification checks the signature, issuer, resource audience, expiry, and a nonempty subject. Issuer defaults to `authorizationServers`; audience defaults to `resource`. An `authorizedParties` allowlist adds a client check and does not replace audience validation. `auth` and `oauth` cannot coexist on the same server.

These URLs are configuration, not credentials. Keep provider secrets in the authorization service. The toolkit does not issue access tokens.

## Require scopes on definitions

```ts [server/mcp/tools/whoami.ts]
import { z } from 'zod'
import { defineMcpTool } from '@nuxtjs/mcp-toolkit/server'

export default defineMcpTool({
  description: 'Read the verified user identifier',
  scopes: ['profile:read'],
  annotations: { readOnlyHint: true, openWorldHint: false },
  outputSchema: z.object({ userId: z.string() }),
  handler: (event) => {
    const userId = event.context.oauth?.sub
    if (!userId) throw new Error('A verified user is required.')
    return { userId }
  },
})
```

`scopesSupported` advertises available scopes; `scopes` requires every named scope on each invocation. Scope claims come from verified `scope` or `scp`. Checks also protect resource-template enumeration and resource/prompt completion callbacks.

Scoped definitions still appear in the authenticated catalog. Protect an endpoint separately when its metadata is sensitive. Authentication and authorization run for the current request; application queries must also enforce ownership and tenant boundaries.

## Configure OAuth per endpoint

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    servers: {
      default: { dir: 'mcp' },
      admin: {
        dir: 'mcp-admin',
        oauth: {
          resource: 'https://example.com/mcp/admin',
          authorizationServers: ['https://auth.example.com'],
          jwt: { jwks: 'https://auth.example.com/.well-known/jwks.json' },
          scopesSupported: ['admin:read'],
        },
      },
    },
  },
})
```

The admin resource has its own metadata path, `/.well-known/oauth-protected-resource/mcp/admin`. Configure the provider's resource indicator and token audience for that exact resource.

## Use provider connectors

Connectors return the same serializable OAuth configuration. Set the provider's configuration before Nuxt evaluates `nuxt.config.ts`.

```ts [nuxt.config.ts]
import { clerk } from 'nitro-mcp-toolkit/oauth/clerk'

export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: { oauth: clerk({ resource: 'https://example.com/mcp' }) },
})
```

Clerk reads `CLERK_PUBLISHABLE_KEY` or `NUXT_PUBLIC_CLERK_PUBLISHABLE_KEY`. Configure resource-bound access tokens with `aud` matching the MCP resource. A client `azp` allowlist does not replace that requirement.

```ts [nuxt.config.ts]
import { okta } from 'nitro-mcp-toolkit/oauth/okta'

export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    oauth: okta({ resource: 'https://example.com/mcp', domain: 'acme.okta.com' }),
  },
})
```

Okta uses a custom authorization server. Pass `issuer` instead of `domain` for a full custom-server URL. Org-server opaque tokens require a custom resource verifier.

```ts [nuxt.config.ts]
import { workos } from 'nitro-mcp-toolkit/oauth/workos'

export default defineNuxtConfig({
  modules: ['@nuxtjs/mcp-toolkit'],
  mcp: {
    oauth: workos({
      resource: 'https://example.com/mcp',
      issuer: 'https://acme.authkit.app',
    }),
  },
})
```

WorkOS uses Connect access tokens with the MCP resource configured as a Resource Indicator. `WORKOS_AUTHKIT_ISSUER` can supply the issuer. AuthKit session tokens or tokens whose audience is only the environment client ID are refused.

Connectors configure verification and discovery. Provider login and client registration still need provider-side setup and testing with the intended MCP clients.

## Use a live verifier when needed

Opaque tokens and runtime callbacks use `createMcpOAuth({ verify })` in a manually composed Nuxt route. The verifier must validate resource binding and populate verified claims when scopes or identity are needed. Mount the returned protected-resource metadata as well; manual route composition does not auto-mount it. See the [manual OAuth wiring example](/examples/authentication#compose-oauth-manually).

## Verify the deployed flow

Check unauthenticated rejection and the metadata URL, valid tokens, wrong audience/issuer, expired tokens, missing scopes, and separate users. Then test the real provider login and refresh flow with each intended client. Local JWT verification does not prove provider login or universal client compatibility.

See [authentication examples](/examples/authentication) and [testing](/advanced/evals).
