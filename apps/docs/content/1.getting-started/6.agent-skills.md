## Inspect the installed version first

The published `manage-mcp` skill describes the documentation version it ships with. This branch documents the 1.0 beta; an older skill or stable 0.x package can describe a different API. Check the module version and use the matching documentation before generating code.

## Install the skill

```sh [Terminal]
npx skills add https://mcp-toolkit.nuxt.dev
```

The production URL follows the deployed docs. While reviewing a beta preview, install or inspect the skill from that preview instead. Docus publishes the discovery catalog at `/.well-known/skills/index.json`.

## Choose the relevant reference

| Reference | Covers |
| --- | --- |
| `tools.md` | Typed input/output, metadata, and Nitro caching |
| `resources.md` | Concrete URIs, templates, contents, and completion |
| `prompts.md` | Arguments, messages, and completion |
| `handlers.md` | Endpoint directories, layers, and composition |
| `oauth.md` | Resource-server setup, providers, claims, and scopes |
| `middleware.md` | Current request context and tool-call hooks |
| `sessions.md` | Application state and legacy sessions |
| `testing.md` | Protocol tests, consumers, and evals |
| `troubleshooting.md` | Migration and common errors |

The source lives in `apps/docs/skills/manage-mcp`. The skill should generate complete Standard Schema definitions and explicit request-context code. It should not recreate removed SDK wrappers, Code Mode, session storage helpers, or built-in MCP Apps.

## Ask for a concrete outcome

Useful requests include “create a typed read-only tool”, “protect this endpoint with OAuth”, “add a resource template with completion”, or “test both protocol eras”. Include the installed toolkit/Nuxt version and expected authorization behavior.

Review generated code and verify it in your application. An agent skill is guidance; it does not replace protocol, authorization, or deployment tests.
